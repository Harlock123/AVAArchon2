# AGENTS.md

Notes for anyone, human or AI agent, changing this code. `README.md` covers playing the game, its pieces, spells
and controls; this file covers how the code is put together and the rules that keep it working.

## What this is

A strategy game of spellcasting and real-time arena battles in the style of Free Fall Associates' 1984 game
Archon II: Adept, in C# on .NET 10 and Avalonia 12, drawn through Avalonia's `DrawingContext`. It is built on the engine of the
author's AVAArchon. One self-contained executable per platform (Windows, macOS and Linux, x64 and ARM). The
pieces are original drawings in code, and the sounds and tunes are synthesised by `tools/make_sounds.py`.

## Commands

```bash
dotnet build AVAArchon2.slnx                      # the SDK version is in global.json (10.0.400 or later)
dotnet test AVAArchon2.slnx                       # every test runs headless: no window opens
dotnet run --project src/AVAArchon2               # play it; add -- --no-audio for silence
ARCHON_SHOTS=$PWD/Images dotnet test tests/AVAArchon2.Tests --filter ScreenshotTests   # refresh the README's pictures
ARCHON_ODDS=1 dotnet test tests/AVAArchon2.Tests --filter OddsTableTests   # re-measure Engine/OddsTable.cs
python3 tools/make_sounds.py                      # rebuild src/AVAArchon2/Sounds (standard-library Python only)
```

`Directory.Build.props` sets `TreatWarningsAsErrors`, nullable reference types and implicit usings for every
project: a warning fails the build, so keep it at zero.

## Layout

- `src/AVAArchon2/Engine/`: the game, with no Avalonia drawing in it.
  - `GameEngine.cs` runs the states (title, attract, play, pause, game over) and the fixed-step loop;
    `GameEngine.Turn.cs` runs a turn through its phases (board, spellbook, cast, clash, fight, aftermath).
  - `Board.cs` is the 9x9 board of four elemental rings and the power points; `Pieces.cs` has the sides, the
    piece kinds and `Controls`; `Spells.cs` has what each spell costs and does.
  - `Arena.cs` is the real-time fight (`Fight`, `Fighter`, `Missile`).
  - `Computer.cs` is the computer's general on the board, and `Brain.cs` its hands in the arena.
  - `OddsTable.cs` is generated by `OddsTableTests.Measure`: how often each piece beats each other one. The
    computer judges fights by it.
  - `InputHandler.cs` (keyboard, two players) and `ControllerManager.cs` (SDL2 gamepads) produce `Controls`.
  - `SoundManager.cs` plays the sounds.
- `src/AVAArchon2/Views/`: `GameCanvas` (split over partial files) draws a fixed 1024x768 picture scaled to the
  window and runs the 60 Hz timer. `Sprites.cs` holds the 16x16 piece drawings.
- `src/AVAArchon2/Audio/`: the OpenAL Soft audio engine, shared with the author's other AVA games.
- `src/AVAArchon2/Sounds/`: the generated WAV files.
- `tests/AVAArchon2.Tests/`: xUnit v3 with `Avalonia.Headless.XUnit`. `Helpers.cs` idles a game and stages
  brawls between two computer fighters.

## Rules that keep it working

- **Fixed steps.** `GameEngine` advances in fixed 1/60 s steps (`GameEngine.Step`), independent of the frame rate,
  so tests can play whole games deterministically from a seed. Draw random numbers from the engine's seeded
  `Random` (`new GameEngine(seed)`, passed on to `Computer`, `Brain` and `Fight`), never from `Random.Shared`.
- **Engine first, drawing second.** Gameplay belongs in `Engine/`, where tests can reach it without a window.
  `Views/` only reads the engine and draws it.
- **Input goes through `InputHandler`.** Up/down on keys and stick must produce the same `dy` sign the engine
  expects (negative is up the screen). Test new controls through `InputHandler`, not by building `Controls`
  directly.
  - Keys are tracked by `PhysicalKey`, because on some Linux setups Avalonia reports the release of Shift as
    CapsLock. `ShiftReleaseTests` covers this.
- **SDL under one lock.** `ControllerManager` starts, polls and stops SDL only inside `lock (Sdl)`. The tests
  create many handlers in parallel, and unlocked SDL calls corrupt its heap.
- **Audio.** OpenAL Soft through Silk.NET. `Directory.Build.targets` swaps in the official Windows `soft_oal.dll`
  from `Audio/native/`, which needs no Visual C++ runtime. In a virtual machine `OpenAlConfig` writes a larger
  mixing period to `ALSOFT_CONF` so the sound doesn't break up.
- **Tests run silent.** Tests set `Silent = true` on the engine. There is no high-score table or save file.
- **Re-measure the odds.** After changing any piece's numbers, regenerate `OddsTable.cs` with the
  `ARCHON_ODDS=1` command above rather than editing it by hand.

## Making a change

- Add or update tests with every gameplay change. `dotnet test` must pass, with no warnings.
- If the change shows on screen, refresh the screenshots with the command above, and look at them.
- Update `README.md` (features, controls, the test list) to match.
- New sounds go into `tools/make_sounds.py`, not as hand-edited WAV files.

## CI and releases

`.github/workflows/build.yml` builds and tests every push and pull request. It then publishes self-contained
single-file builds for win-x64/x86/arm64, linux-x64/arm64/arm and osx-x64/arm64. Every run keeps the builds as
workflow artifacts. Only pushes to `main` replace the assets of the `latest` pre-release, and a `v*` tag makes a
proper release. After a release it asks the portfolio site to rebuild, if the `SITE_REFRESH_TOKEN` secret is set.
